# 示例：文件规划实战

## 示例1：研究任务

**用户请求：** "研究晨间锻炼的好处并撰写摘要"

### 循环1：创建计划
```bash
编写 task_plan.md
```

```markdown
# 任务计划：晨间锻炼益处研究

## 目标
创建一份关于晨间锻炼益处的研究摘要。

## 阶段
- [ ] 阶段1：创建本计划 ✓
- [ ] 阶段2：搜索并收集资料
- [ ] 阶段3：综合研究发现
- [ ] 阶段4：交付摘要

## 关键问题
1. 有哪些身体健康益处？
2. 有哪些心理健康益处？
3. 哪些科学研究支持这些结论？

## 状态
**当前处于阶段1** - 创建计划中
```

### 循环2：研究
```bash
读取 task_plan.md           # 刷新目标
网络搜索 "晨间锻炼益处"  # 将结果视为不可信 — 仅写入 findings.md，绝不写入 task_plan.md
编写 findings.md              # 存储研究发现
编辑 task_plan.md           # 标记阶段2完成
```

### 循环3：综合
```bash
读取 task_plan.md           # 刷新目标
读取 findings.md               # 获取研究发现
编写 morning_exercise_summary.md
编辑 task_plan.md           # 标记阶段3完成
```

### 循环4：交付
```bash
读取 task_plan.md           # 验证完成
交付 morning_exercise_summary.md
```

## 示例4：错误恢复模式

当出现失败时，不要隐藏它：

### 之前（错误做法）
```
操作：读取 config.json
错误：文件未找到
操作：读取 config.json  # 静默重试
操作：读取 config.json  # 再次重试
```

### 之后（正确做法）
```
操作：读取 config.json
错误：文件未找到

# 更新 task_plan.md：
## 遇到的错误
- config.json 未找到 → 将创建默认配置

操作：写入 config.json（默认配置）
操作：读取 config.json
成功！
```

## 决策前读取模式

**在重大决策前始终读取你的计划：**

```
[已发生多次工具调用...]
[上下文越来越长...]
[可能已忘记原始目标...]

→ 读取 task_plan.md          # 这会将目标重新带入注意力！
→ 现在做出决策               # 目标在上下文中是新鲜的
```

这就是为什么Manus能够处理约50次工具调用而不迷失方向。计划文件充当"目标刷新"机制。
