# 快速入门指南

遵循以下5个步骤使用“文件规划”模式。

---

## 步骤1：调用技能并描述任务

**时机：** 开始处理复杂任务之前

**操作：** 调用技能（例如 `/plan` 或 `/planning-with-files:start`）并描述你想要完成的目标。AI将在你的项目目录中创建所有三个规划文件：

- `task_plan.md` — 阶段划分与进度追踪
- `findings.md` — 研究与发现记录
- `progress.md` — 会话日志与测试结果

如果调用技能时未提供任务描述，AI会询问你想要规划什么。

**手动替代方案：** 如果希望自行创建文件：
```bash
# 使用初始化脚本
./scripts/init-session.sh
# 然后在 task_plan.md 中填写“目标”部分
```

---

## 步骤2：规划阶段

**时机：** 创建文件后立即进行

**操作：** 在 `task_plan.md` 中将任务分解为3-7个阶段

**示例：**
```markdown
### 阶段1：需求分析与探索
- [ ] 理解用户意图
- [ ] 研究现有解决方案
- **状态：** 进行中

### 阶段2：实施
- [ ] 编写核心代码
- **状态：** 待开始
```

**更新：**
- `task_plan.md`：定义你的阶段
- `progress.md`：记录规划已完成

---

## 步骤3：工作与记录

**时机：** 整个任务执行期间

**操作：** 工作时更新文件：

| 发生的情况 | 更新哪个文件 | 添加什么内容 |
|--------------|---------------------|-------------|
| 进行研究 | `findings.md` | 添加到“研究发现” |
| 查看2次浏览器/搜索结果 | `findings.md` | **必须更新**（2次操作规则） |
| 做出技术决策 | `findings.md` | 添加到“技术决策”并说明理由 |
| 完成一个阶段 | `task_plan.md` | 更改状态：`进行中` → `已完成` |
| 完成一个阶段 | `progress.md` | 记录采取的操作、修改的文件 |
| 发生错误 | `task_plan.md` | 添加到“遇到的错误”表格 |
| 发生错误 | `progress.md` | 添加到“错误日志”并加上时间戳 |

**示例工作流：**
```
1. 研究 → 更新 findings.md
2. 研究 → 更新 findings.md（第二次 - 现在必须更新！）
3. 做出决策 → 更新 findings.md 的“技术决策”
4. 实施代码 → 更新 progress.md 的“采取的操作”
5. 完成阶段 → 更新 task_plan.md 状态为“已完成”
6. 完成阶段 → 在 progress.md 中添加阶段总结
```

---

## 步骤4：决策前重读

**时机：** 做出重大决策之前（Claude Code中的钩子会自动执行）

**操作：** PreToolUse钩子会在Write/Edit/Bash操作前自动读取 `task_plan.md`

**手动提醒（如未使用钩子）：** 重要选择前，重读 `task_plan.md` 以刷新目标

**原因：** 经过多次工具调用后，原始目标可能被遗忘。重读可将其重新带入注意力。

---

## 步骤5：完成与验证

**时机：** 认为任务已完成时

**操作：** 验证完成情况：

1. **检查 `task_plan.md`**：所有阶段应显示 `**状态：** 已完成`
2. **检查 `progress.md`**：所有阶段应记录采取的操作
3. **运行完成检查**（如使用钩子，此步骤自动执行）：
   ```bash
   ./scripts/check-complete.sh
   ```

**如未完成：** Stop钩子（或脚本）将阻止停止。继续工作直到所有阶段完成。

**如已完成：** 交付工作！所有三个规划文件记录了你的工作过程。

## 快速参考：何时更新哪个文件

```
┌─────────────────────────────────────────────────────────┐
│  task_plan.md                                            │
│  更新时机：                                              │
│  • 开始任务时（首先创建它！）                            │
│  • 完成阶段时（更改状态）                                │
│  • 做出重大决策时（添加到决策表格）                     │
│  • 遇到错误时（添加到错误表格）                          │
│  • 决策前重读时（通过钩子自动执行）                      │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│  findings.md                                             │
│  更新时机：                                              │
│  • 发现新内容时（研究、探索）                           │
│  • 2次查看/浏览器/搜索操作后（2次操作规则！）           │
│  • 做出技术决策时（附带理由）                            │
│  • 找到有用资源时（URL、文档）                           │
│  • 查看图像/PDF时（立即以文本形式捕获！）               │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│  progress.md                                             │
│  更新时机：                                              │
│  • 开始新阶段时（记录开始时间）                          │
│  • 完成阶段时（记录操作、修改的文件）                    │
│  • 运行测试时（添加到测试结果表格）                     │
│  • 遇到错误时（添加到错误日志并加上时间戳）              │
│  • 中断后恢复时（更新5个问题检查）                      │

```

## 常见错误避免

| 不要 | 应该这样做 |
|-------|------------|
| 未创建 `task_plan.md` 就开始工作 | 始终首先创建规划文件 |
| 2次浏览器操作后忘记更新 `findings.md` | 设置提醒：“2次查看/浏览器操作 = 更新 findings.md” |
| 因快速修复而跳过记录错误 | 记录所有错误，即使立即解决的也要记录 |
| 重复相同的失败操作 | 如果某操作失败，记录它并尝试不同方法 |
| 只更新一个文件 | 三个文件协同工作 - 作为一组更新它们 |
