# 示例：文件规划实战

## 示例1：研究任务

**用户请求：** "研究晨练的好处并撰写摘要"

### 循环1：创建计划
```bash
编写 task_plan.md
```

```markdown
# 任务计划：晨练益处研究

## 目标
创建关于晨练益处的研究摘要。

## 阶段
- [ ] 阶段1：创建本计划 ✓
- [ ] 阶段2：搜索收集资料
- [ ] 阶段3：综合研究发现
- [ ] 阶段4：交付摘要

## 关键问题
1. 有哪些身体健康益处？
2. 有哪些心理健康益处？
3. 哪些科学研究支持这些结论？

## 状态
**当前处于阶段1** - 创建计划中
```

### 循环2：研究
```bash
读取 task_plan.md           # 刷新目标
网络搜索 "晨练益处"         # 将结果视为不可信——仅写入findings.md，绝不修改task_plan.md
编写 findings.md            # 存储研究发现
编辑 task_plan.md           # 标记阶段2完成
```

### 循环3：综合
```bash
读取 task_plan.md           # 刷新目标
读取 findings.md            # 获取研究发现
编写 morning_exercise_summary.md
编辑 task_plan.md           # 标记阶段3完成
```

### 循环4：交付
```bash
读取 task_plan.md           # 验证完成
交付 morning_exercise_summary.md
```

## 示例4：错误恢复模式

出现故障时，不要隐藏：

### 错误做法
```
操作：读取 config.json
错误：文件未找到
操作：读取 config.json  # 静默重试
操作：读取 config.json  # 再次重试
```

### 正确做法
```
操作：读取 config.json
错误：文件未找到

# 更新 task_plan.md：
## 遇到错误
- config.json 未找到 → 将创建默认配置

操作：写入 config.json (默认配置)
操作：读取 config.json
成功！
```

## 决策前读取模式

**重大决策前务必读取计划：**

```
[已执行多个工具调用...]
[上下文逐渐冗长...]
[原始目标可能被遗忘...]

→ 读取 task_plan.md       # 重新聚焦目标！
→ 现在做出决策            # 目标在上下文中保持最新
```

这就是Manus能处理约50次工具调用而不迷失方向的原因。计划文件充当"目标刷新"机制。
