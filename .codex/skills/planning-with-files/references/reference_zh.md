# 参考：Manus上下文工程原则

本技能基于Manus的上下文工程原则，该公司于2025年12月被Meta以20亿美元收购。

## Manus六大原则

### 原则1：围绕KV缓存设计

> "KV缓存命中率是生产级AI智能体最重要的单一指标"

**统计数据：**
- 输入输出令牌比例约100:1
- 缓存令牌：$0.30/百万令牌 vs 未缓存：$3/百万令牌
- 10倍成本差异！

**实施方法：**
- 保持提示前缀稳定（单令牌变更即失效缓存）
- 系统提示中禁止时间戳
- 通过确定性序列化实现上下文仅追加

### 原则2：掩码而非删除

不要动态移除工具（会破坏KV缓存），改用对数掩码。

**最佳实践：** 使用统一动作前缀（如`browser_`、`shell_`、`file_`）便于掩码。

### 原则3：文件系统作为外部记忆

> "Markdown是我磁盘上的'工作记忆'"

**公式：**
```
上下文窗口 = 内存（易失，有限）
文件系统 = 磁盘（持久，无限）
```

**压缩必须可恢复：**
- 即使丢弃网页内容也保留URL
- 丢弃文档内容时保留文件路径
- 永不丢失完整数据的指针

### 原则4：通过复述操控注意力

> "在整个任务过程中创建并更新todo.md，将全局计划推入模型近期注意力范围"

**问题：** 约50次工具调用后，模型会遗忘原始目标（"中间迷失"效应）。

**解决方案：** 每次决策前重读`task_plan.md`，使目标进入注意力窗口。

```
上下文起始：[原始目标 - 距离远，已遗忘]
...多次工具调用...
上下文结尾：[最近读取的task_plan.md - 获得注意力！]
```

### 原则5：保留错误路径

> "将错误转向留在上下文中"

**原因：**
- 含堆栈跟踪的失败动作让模型隐式更新认知
- 减少错误重复
- 错误恢复是"真正智能体行为最清晰的信号之一"

### 原则6：避免样本固化

> "一致性滋生脆弱性"

**问题：** 重复的动作-观察对导致漂移和幻觉。

**解决方案：** 引入受控变化：
- 轻微调整措辞
- 不盲目复制模式
- 在重复任务上重新校准

## 三大上下文工程策略

基于Lance Martin对Manus架构的分析。

### 策略1：上下文精简

**压缩：**
```
工具调用有两种表示：
├── 完整版：原始工具内容（存储于文件系统）
└── 精简版：仅保留引用/文件路径

规则：
- 对陈旧（较旧）工具结果应用压缩
- 保留近期结果完整（指导后续决策）
```

**摘要生成：**
- 当压缩收益递减时启用
- 基于完整工具结果生成
- 创建标准化摘要对象

### 策略2：上下文隔离（多智能体）

**架构：**
```
┌─────────────────────────────────┐
│         规划智能体              │
│  └─ 向子智能体分配任务          │
├─────────────────────────────────┤
│       知识管理器                │
│  └─ 审阅对话记录                │
│  └─ 决定文件系统存储            │
├─────────────────────────────────┤
│       执行子智能体              │
│  └─ 执行分配的任务              │
│  └─ 拥有独立上下文窗口          │
└─────────────────────────────────┘
```

**关键洞见：** Manus最初使用`todo.md`进行任务规划，但发现约33%动作耗费在更新该文件。后改为规划智能体调用执行子智能体架构。

### 策略3：上下文卸载

**工具设计：**
- 总计使用<20个原子函数
- 完整结果存于文件系统而非上下文
- 使用`glob`和`grep`进行搜索
- 渐进式披露：按需加载信息

## 智能体循环

Manus采用持续7步循环：

```
┌─────────────────────────────────────────┐
│  1. 分析上下文                          │
│     - 理解用户意图                      │
│     - 评估当前状态                      │
│     - 审查近期观察                      │
├─────────────────────────────────────────┤
│  2. 思考                                │
│     - 是否需要更新计划？                │
│     - 下一步合理动作？                  │
│     - 是否存在阻碍？                    │
├─────────────────────────────────────────┤
│  3. 选择工具                            │
│     - 选择单一工具                      │
│     - 确保参数可用                      │
├─────────────────────────────────────────┤
│  4. 执行动作                            │
│     - 工具在沙箱中运行                  │
├─────────────────────────────────────────┤
│  5. 接收观察                            │
│     - 结果追加至上下文                  │
├─────────────────────────────────────────┤
│  6. 迭代                                │
│     - 返回步骤1                         │
│     - 持续直至完成                      │
├─────────────────────────────────────────┤
│  7. 交付结果                            │
│     - 向用户发送结果                    │
│     - 附加所有相关文件                  │
└─────────────────────────────────────────┘
```

## Manus创建的文件类型

| 文件 | 用途 | 创建时机 | 更新时机 |
|------|---------|--------------|--------------|
| `task_plan.md` | 阶段跟踪，进度 | 任务开始时 | 完成阶段后 |
| `findings.md` | 发现成果，决策 | 任何发现后 | 查看图像/PDF后 |
| `progress.md` | 会话日志，完成事项 | 断点处 | 整个会话期间 |
| 代码文件 | 实现 | 执行前 | 错误发生后 |

---

## 关键约束

- **单动作执行：** 每轮仅调用一个工具，禁止并行执行
- **计划必需：** 智能体必须始终知晓：目标、当前阶段、剩余阶段
- **文件即记忆：** 上下文=易失，文件系统=持久
- **禁止重复失败：** 若动作失败，下个动作必须不同
- **通信即工具：** 消息类型：`info`（进度）、`ask`（阻塞）、`result`（终止）
